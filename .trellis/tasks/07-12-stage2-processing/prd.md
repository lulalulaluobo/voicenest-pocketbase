# 阶段 2：ASR 转写、LLM 整理与多目标同步 需求文档

## 目标

实现 Voice Inbox 核心自动化管道的第二部分：将本地已保存的录音通过 API 调用进行 ASR 转写、LLM 整理，并自动/手动同步到已启用的 Obsidian 与微信公众号草稿箱目标。

## 已知信息

- **ASR 服务**：推荐默认 `stepaudio-2.5-asr`（阶跃星辰），同时也需兼容标准的 OpenAI Whisper 接口格式。需要用户提供 API Key，并在设置页中提供“测试连接”功能。
- **LLM 服务**：支持标准 OpenAI 兼容的 Chat Completions 接口，供用户自主配置 Base URL、API Key 与 Model 名称。支持测试连接。模型须输出包含 `title` 和 `markdown` 的 JSON。
- **笔记类型定制**：
  - 每种类型（如随想、日记、会议、项目）可以在设置页中被定义独立的目标路径、提示词（Prompt）、Markdown 模板、默认标签。
  - 每种类型可单独覆盖全局 LLM 选项（如单独选用高阶模型处理会议，低阶处理随想）。
- **同步终端**：调用 Fast Note Sync 本地/远程 API，将 Markdown 文件写入到用户 Obsidian 对应的目录路径中。
- **公众号草稿箱**：通过受 Cloudflare Access 保护的 Worker 调用微信公众号草稿接口。Worker 将 AppID、Secret 与默认封面 `media_id` 保存为密钥；PWA 只保存 Worker 地址和开关。
- **交互流程**：
  - 音频卡片与详情页显示处理状态（待处理、等待网络、处理中、已同步、失败）。
  - 支持手动触发“上传并整理”、“重新整理”（重新调用 ASR+LLM）、“重新同步”（仅重试已启用目标）。已有公众号草稿时更新同一草稿，不新建重复稿。
  - 自动处理配置：允许用户在“设置”中开启“录音完成后自动处理”，从而在后台或静默期间自动完成全部 ASR、LLM 与同步动作。

## 临时假设

- 自动处理和网络连接监控使用标准浏览器 `navigator.onLine` 事件，并在页面处于前台时进行队列处理。
- ASR 转换因为受前端环境和网络限制，单条最大限制 30 分钟音频，首版不设计前端大文件分片合并转写。

## 决策 (ADR-lite)

- **处理流程**：采用全自动流水线（ASR -> LLM -> Sync 连续执行），无需用户确认即可完成，但允许用户事后在详情页编辑原始文本并重新触发。
- **重试机制**：由于整体流程简短，不支持分步颗粒度重试，调用失败时仅支持从失败点（或整体）重新整理与同步。
- **存储管理**：本地音频分片与转写结果在同步成功后将永久保留在 IndexedDB 中，由用户手动决定何时删除。
- **队列容灾**：网络恢复且 PWA 在前台时，自动顺次处理在等待网络状态的任务。

## 需求列表 (Evolving Requirements)

- [ ] 实现设置页中的 ASR、LLM 和 Fast Note Sync 全局参数配置表单。
- [ ] 实现针对 ASR 和 LLM 配置的“测试连接”功能。
- [ ] 实现设置页中笔记类型的 CRUD 管理（包括路径、专用提示词和模板配置）。
- [ ] 扩展 `Recording` 数据库实体，添加 `transcript` (原始转写)、`summary` (整理成果) 字段以及 `errorMessage`。
- [ ] 实现 ASR 请求封装，能将 IndexedDB 内的分片拼合后的 Blob 作为 Multipart Form Data 上传。
- [ ] 实现 LLM 请求封装，利用提示词/JSON Schema 强制格式化输出 JSON。
- [ ] 实现 Fast Note Sync 接口的 HTTP 调用。
- [ ] 实现微信公众号草稿 Worker、令牌缓存与 7 天幂等保护；仅创建/更新草稿，不自动正式发布。
- [ ] 设置页可配置公众号同步开关和 Worker 地址，并测试 Access、IP 白名单与草稿权限；列表及详情页展示公众号草稿状态。
- [ ] 在音频详情页展示转写及整理 Markdown 文本，并支持文本编辑与操作按钮（重新整理、重新同步）。
- [ ] 在主页及列表页增加各卡片对应状态指示及手动整理触发动作。
- [ ] 实现录音结束后的“自动整理/同步”异步任务流（结合网络监测机制）。

## 验收标准 (Acceptance Criteria)

- [ ] 用户可以通过设置表单成功配置并保存 API 信息，通过“测试连接”可以得到预期的 ASR/LLM 测试通过响应。
- [ ] 录音结束后，手动点击“上传并整理”后：
  1. 卡片状态变更为 `处理中`；
  2. ASR 成功返回文本并写入数据库；
  3. LLM 成功返回整理结构并更新本地详情；
  4. 调用 Fast Note Sync 将笔记按路径和模板成功写入 Obsidian，状态置为 `已同步`。
- [ ] 在详情页中修改整理后的 Markdown 文本并点击“重新同步”，能覆盖写入或另存到 Obsidian 中。
- [ ] 启用公众号目标后，整理的 Markdown 会保存到公众号草稿箱；Obsidian 或公众号任一失败不会阻断另一目标，失败信息可见且可单独重试。
- [ ] 断网情况下进行录音且开启了“自动处理”，卡片自动进入 `等待网络` 状态。网络恢复后（`navigator.onLine` 为 true 且页面在前台），应用能自动触发转写和同步。

## 团队质量标准 (DoD)

- 新增 API 模块和状态管理应当在 `src/lib/` 进行单元测试（例如 Mock ASR/LLM/Sync 请求）。
- `npm run test` 与 `npm run build` 无任何警告与报错。

## 显式排除范围 (Out of Scope)

- 自建中转后端服务器。
- Web 端的音频文件压缩或降采样编码（完全依赖 MediaRecorder 输出的原始 webm/mp4 格式）。
- 自动清理音频分片的策略管理（首版仅限手动删除）。
- 强制 ASR 确认后再进行整理的交互阻断。
- 公众号自动正式发布、评论管理、多账号切换、正文图床与社区功能。
