# 公众号人工二次改写设计

**状态**：已获用户确认，待审阅  
**目标**：保留“个人笔记默认同步 Obsidian”，将公众号改为独立的人工二次改写与草稿发布流程，使两种文章风格互不覆盖。

## 已确认需求

- 任何“重新整理”操作先要求二次确认，防止列表与详情页误触。
- ASR 与 LLM 生成的个人笔记仍按现有笔记分类模板整理，并默认同步 Obsidian。
- 不再因公众号配置已填写或已启用而自动创建、更新公众号草稿。
- 对已有个人笔记的录音，在列表中提供微信图标入口，进入独立的公众号编辑页。
- 编辑页提供三种可复用、可编辑的本地提示词模板：观点随笔、知识分享、日常记录。
- 用户选择并可修改提示词后，手动调用现有 LLM 进行公众号风格改写；再手动修改标题和正文；最后创建或更新草稿箱。
- 不自动正式发布，不增加公众号草稿列表、CMS、正文图床或后端账号系统。

## 流程

```text
录音 → ASR → 个人笔记 LLM 整理 → 默认同步 Obsidian
                                   └─ 用户点击微信图标
                                        → 查看个人笔记（只读参考）
                                        → 选择/编辑公众号提示词
                                        → LLM 二次改写
                                        → 人工编辑标题与正文
                                        → 创建或更新公众号草稿
```

公众号改写失败、授权失效或发布失败只更新公众号子状态；不得把已有个人笔记、Obsidian 同步结果或录音总状态改为失败。

## 数据与界面

### 本机配置

- `WechatDraftConfig.enabled` 改为“启用公众号草稿编辑功能”，仅控制手动入口可用性。
- 配置继续只保存 Worker URL 和启用状态；AppID、AppSecret、封面素材 ID 仍只保存在 Worker Secret。
- 新增本地 `WechatPromptTemplate[]`，初始包含观点随笔、知识分享、日常记录。每项只有 `id`、`name`、`prompt`；在公众号编辑页修改后直接保存，供后续复用。

### 录音记录

新增独立字段 `wechatTitle`、`wechatMarkdown`，与已有 `wechatDraftMediaId`、`wechatStatus`、`wechatErrorMessage`、`wechatRequestId` 一起保存。

- `summary` 始终是个人笔记，不被公众号改写覆盖。
- 首次发布没有 `wechatDraftMediaId` 时调用 `draft/add`；已有该 ID 时调用 `draft/update`。
- 每次发布生成新的请求 ID；发布成功后保存草稿 ID 和状态。

### 列表与详情

- 列表中的“重新整理”及详情页“重新整理生成”在执行前使用原生确认框；确认后才触发 ASR/LLM。
- 有 `summary` 的卡片展示微信图标按钮。公众号编辑未启用或未配置时，按钮禁用并给出明确提示。
- 公众号编辑页显示个人笔记 Markdown 参考区、模板选择器、可编辑提示词、改写按钮、可编辑公众号标题与正文，以及“发布到草稿箱”按钮。
- 设置页的开关文案改为“启用公众号草稿编辑”，不再出现“整理完成后同步到公众号草稿箱”。

## 复用与边界

- 复用现有 LLM 配置、`formatNote` 的 JSON 输出约束与 Worker `POST /drafts`；不创建第二套 Worker 或公众号 API。
- 复用现有 Cloudflare Access、默认封面、KV token 缓存和草稿幂等机制。
- 不引入富文本编辑器或新的依赖；编辑页使用现有 textarea 与原生 select。
- 已由第一版自动同步创建的草稿保留；用户可通过新的编辑页继续修改和更新该草稿。

## 验收与测试

- 处理流水线仅同步已配置的 Obsidian，不调用公众号发布客户端。
- “重新整理”在用户取消确认时不启动处理。
- 三种初始模板可选择、编辑并在重开应用后保留。
- 公众号二次改写成功后只写入 `wechatTitle` 与 `wechatMarkdown`；个人 `summary` 不变。
- 首次发布创建草稿，再次发布更新同一 `wechatDraftMediaId`。
- Worker 授权、白名单或发布失败时，编辑页显示中文错误，可修改后再次发布。
- 现有前端与 Worker 测试、构建继续通过。
