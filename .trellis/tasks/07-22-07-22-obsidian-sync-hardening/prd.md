# 修复 Obsidian 同步可靠性与安全边界

## 目标

让公共 PocketBase 后端上的 Obsidian 单向同步具备明确的隐私边界、可重试的幂等队列、可证明的 Vault ACK 状态，以及可控的容量和 Token 生命周期；同时修复相关客户端安全与体验缺陷。

## 已知事实

- 当前架构为 VoiceNest 写入 `obsidian_notes`，插件拉取、写入 Vault 后 ACK。
- 正文目前以明文临时存储于 PocketBase；README 的“文本绝不上云”表述不正确。
- 入队后本地状态立即标为 `synced`，但插件尚未确认 Vault 写入。
- 队列没有稳定的本地录音身份、数量/TTL 限制或用户可撤销的 Token 管理。
- 后端地址切换未清除 PocketBase 认证状态，客户端与插件均未强制 HTTPS。

## 范围

1. 为队列增加稳定 `sourceId` 与用户内唯一性；重复入队更新同一待同步笔记。
2. 将本地状态拆分为已处理、已入队、已确认同步；ACK 保留无正文回执，延迟清理。
3. 通过自定义后端接口实施正文大小、待同步数量、TTL、Token 数量与限流；关闭通用队列写入。
4. 实现 Token 列表、撤销、最后使用时间；原始 Token 只在创建时返回。
5. 修复后端切换的 Token 隔离与 HTTPS 校验；插件采用同一策略。
6. 修复录音资源释放、Obsidian 双 H1、微信凭据校验和 APK 未知来源安装续装体验。
7. 更新 README 与 Trellis 同步契约，准确说明服务器临时明文队列的边界。

## 非范围

- 本任务不实施正文端到端加密；它需要独立的同步密钥管理、迁移和恢复设计。先如实披露临时明文存储。
- 不改变 ASR、LLM、微信草稿箱的模型和业务能力。

## 验收标准

- [ ] 同一录音重复入队不会生成第二个 Vault 文件。
- [ ] 只有插件 ACK 后本地记录才显示“已同步”并执行“立即清理音频”。
- [ ] 断网重试、过期队列、过量队列和失效 Token 都有可预期的错误或清理行为。
- [ ] 用户可查看并撤销自己的同步 Token，原始 Token 不会再次返回。
- [ ] 非 HTTPS 的生产后端地址被拒绝，切换地址后旧登录态被清除。
- [ ] README 不再声称同步正文从不上云。
- [ ] 单元测试、前端构建、插件构建通过。

## 技术决策

- ACK 后删除正文队列记录，同时保留只含 `owner`、`sourceId`、`ackedAt` 的同步回执 7 天；客户端据此确认真实同步，避免正文在 ACK 后继续留存。
- 队列写入改为自定义 API，由服务器确定 owner、执行限额与 upsert；不再向普通用户开放通用 Collection 写入。
- 允许 HTTP 仅限 `localhost`、`127.0.0.1` 和 Android 模拟器 `10.0.2.2`；其余地址必须 HTTPS。
